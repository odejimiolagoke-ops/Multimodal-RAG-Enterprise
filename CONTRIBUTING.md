# Contributing

Contributions of bug fixes, documentation, and focused improvements are
welcome. For substantial or behavior-changing work, open an issue first to
discuss the approach.

## Before proposing a change

1. Check existing issues and pull requests to avoid duplicate work.
2. Keep changes focused and explain the user problem they address.
3. Do not include credentials, private data, generated environment files, or
   unrelated local artifacts.

## Pull requests

Include the following in a pull request:

- A concise description of the change and its motivation.
- Any relevant issue or discussion link.
- Tests or manual checks performed, and any limitations.
- Notes about configuration, compatibility, or migration impacts.

Keep each pull request reviewable. Update it in response to review feedback,
and do not merge your own change unless a maintainer has explicitly delegated
that responsibility.

## Validation

Run checks relevant to the code you changed and report their results. If the
project does not yet have an automated check for the affected behavior, include
the manual steps used to validate it and consider adding a suitable test.

## Community expectations

All contributors are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
For security-sensitive reports, follow the private reporting guidance in
[Security](SECURITY.md) rather than opening a public issue.
